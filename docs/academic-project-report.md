# Skill-Swap academic project report draft

## Abstract

Skill-Swap is a secure web-based peer-to-peer skill exchange platform that enables members to teach skills they know and learn skills they want. The system verifies teaching competency through randomized skill assessments, recommends reciprocal matches, provides protected one-to-one communication and video sessions, stores authorized recording metadata, and generates a verifiable certificate after an eligible exchange is completed. An administrator portal provides platform monitoring, moderation, question-bank management, session oversight, support operations, certificate controls, and immutable audit visibility.

## Objectives

The project objectives are to create a trustworthy peer-learning environment, reduce unqualified teaching through per-skill assessments, match members according to complementary teach/learn goals, support real-time communication and video learning, preserve a record of successful exchanges, and provide administrators with tools to keep the platform safe and connected to its users.

## Technology used

The frontend uses React.js with Tailwind CSS and Bootstrap-compatible component styling. Django with Python exposes REST API boundaries and contains the business rules. MongoDB stores flexible application documents. JWT and bcrypt provide authentication and password hashing. Socket.io supports real-time chat, typing, presence, and notification events. ZegoCloud provides video-room functionality and recording events. Cloudinary stores profile images, certificate assets, and authorized media references. Gmail SMTP sends OTP and platform notifications. Render hosts the Django and Socket.io services, while Netlify or Vercel hosts the React frontend.

## Modules

1. **Authentication and Profile**: registration, email OTP, login, password reset, onboarding, profile editing, privacy, availability, and avatar handling.
2. **Skill Assessment and Certification**: skill catalogue, versioned question bank, randomized 30–40 question attempts, server-side scoring, per-skill verification, completion confirmation, and certificate validation.
3. **Matching and Chat**: reciprocal matching, explainable ranking, request states, blocking/reporting, authorized Socket.io conversations, persisted messages, typing, presence, and unread notifications.
4. **Video Call and Recording**: session scheduling, participant authorization, server-issued ZegoCloud credentials, explicit recording consent, recording status, Cloudinary references, disputes, and completion lifecycle.
5. **Administration**: metrics, activity monitor, user management, skill/question management, assessment monitoring, matches, communication metadata, sessions, recordings, reports, certificates, announcements, support, settings, and audit logs.

## Architecture

The React client sends ordinary operations to Django through HTTPS JSON endpoints. Django validates JWT identity, role, ownership, and state transitions before reading or writing MongoDB. Socket.io provides a separate JavaScript real-time service because Socket.io server functionality is JavaScript-based; it validates the shared JWT contract and consults Django before joining a private conversation room. ZegoCloud is reached from the browser only with a short-lived participant-scoped token generated by Django. SMTP, Cloudinary, MongoDB, and ZegoCloud server secrets remain in environment configuration.

## Security and privacy

The design uses bcrypt password hashing, JWT expiry, role-based authorization, email verification, rate limits, server-side assessment scoring, protected two-person rooms, signed expiring media URLs, upload restrictions, CORS allowlists, secure headers, input validation, activity logs, and immutable audit events. Recording is opt-in and visible. Administrator access to private message or recording content is exceptional, reasoned, permission-checked, and audited.

## Testing

Tests cover scoring, pass thresholds, reciprocal matching, conversation authorization, certificate eligibility, state transitions, API authorization, Socket.io room authorization, provider-adapter failure paths, OTP expiry, invalid JWTs, suspended accounts, unauthorized recording access, duplicate certificate issuance, public certificate verification, responsive layouts, accessibility, and the complete member-to-certificate journey. Administrative tests cover activity filters, moderation actions, audit creation, report resolution, certificate revocation, and announcement delivery states.

## Limitations and future scope

The academic MVP focuses on one-to-one exchanges and a controlled skill catalogue. Future work may include group sessions, richer availability calendars, mobile applications, multi-language assessments, institution accounts, improved recommendation models, and additional analytics. Any expansion must retain the trust principles of explainable matching, explicit consent, privacy-aware monitoring, and auditable administration.
